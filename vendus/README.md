# Vendus SDK

TypeScript (bun) SDK and data-fetch scripts for the Cegid Vendus POS API, used to pull
A20 sales data for reporting and analysis.

## Setup

1. `bun install` (needs [bun](https://bun.sh) — `curl -fsSL https://bun.sh/install | bash`)
2. Get an API key in Vendus under **Apps > API** (requires Flex or Pro plan).
3. Store it in the macOS Keychain:
    ```sh
    bun run auth          # interactive: paste the key (masked), validated live
    bun run auth status   # show masked key + validate
    bun run auth clear    # remove it
    ```
    Scripts resolve the key as: `VENDUS_API_KEY` env var first (override), then
    Keychain (service `a30-vendus-api-key`).

> ⚠️ The API key carries the full (write-capable) permissions of the user it belongs
> to. These scripts only ever perform GET requests.

## Scripts

All scripts are self-documenting — run any of them with `--help`. They print JSON
to stdout (or `--out <file>`) and progress to stderr.

### P&L data for a period

```sh
bun run fetch:pnl -- --since 2026-06-01 --until 2026-06-30 [--store-id 123] [--skip-details] [--out pnl.json]
```

Fetches all FT/FS/FR/NC documents **with per-document line items** (product, qty,
net/gross amounts — the basis for product-dependent expenses) plus `product_costs`,
a trimmed catalog with each product's current `supply_price` to join COGS onto the
items sold. Note: line items don't record historical cost, so COGS uses the current
supply price. As cross-checks it also pulls `/reports/daily`, `/reports/products`
(both include server-computed **profit**), and `/reports/monthly`. Includes a
computed summary: revenue gross/net (sales minus credit notes) and totals by
document type. `--skip-details` skips the per-document line-item calls.

### Daily sales issue analysis

```sh
bun run fetch:daily -- --date 2026-07-09 [--until 2026-07-10] [--store-id 123] [--skip-details] [--out daily.json]
```

Fetches every document in the period (all types and statuses, including canceled),
plus per-document detail — line items, payments, `related_docs` (credit note →
original invoice links), user, timestamps — decode tables for type/payment codes,
and cash movements per register. `--skip-details` skips the per-document detail
calls (1 request per document, 5 concurrent) when only headline data is needed.

## Layout

Three layers — business logic is importable without any CLI:

- `src/vendus_api_client.ts` — hand-written thin wrapper (`VendusApiClient`) exposing
  `account`, `documents`, `reports`, `registers`, `products` namespaces
- `src/fetchers/` — low-level composable fetch functions (documents + per-document
  details, period reports, product costs, register movements, decode tables). Pure:
  take a client + params, return typed data, optional `onProgress` callback.
- `src/usecases/` — high-level composed flows: `buildPnlData`, `buildDailySales`.
  Orchestrate fetchers and compute summaries; return the full payload object.
- `scripts/` — thin commander CLI shells: parse args, resolve the API key, wire
  progress to stderr, emit JSON. No business logic.
- `src/generated/vendus/hey-api/` — generated by `@hey-api/openapi-ts` from
  `../docs/vendus-api/vendus-api-v1.2.openapi.json`; never edit, regenerate with
  `bun run openapi:generate` (after refreshing the spec via
  `../scripts/fetch-vendus-api-docs.sh`)
- `src/utils/` — error mapping, pagination (`page`/`per_page`, max 1000), concurrency,
  numbers, Keychain access

### Composing custom analyses

For ad-hoc questions, import the layers directly instead of shelling out to CLIs:

```ts
import { VendusApiClient } from './src/vendus_api_client';
import { getVendusApiKey } from './src/utils/keychain';
import { fetchDocuments, fetchDocumentDetails } from './src/fetchers/fetch_documents';

const client = new VendusApiClient({ apiKey: getVendusApiKey()! });
const docs = await fetchDocuments(client, {
    since: '2026-06-01',
    until: '2026-06-30',
    types: 'NC',
});
const details = await fetchDocumentDetails(client, docs);
```

## Vendus spec quirks the wrapper compensates for

- List responses are declared as single objects in the spec; the API returns arrays —
  wrapper methods re-type them.
- Auth is not machine-encoded (`securitySchemes` empty) — the client sends HTTP Basic
  with the key as username (same as the official PHP SDK).
- `page`/`per_page` pagination params and the `{id}` path param of
  `/registers/{id}/movements` are missing from the spec — added/cast in the wrapper.
- The `status` filter enum holds display strings ("N - Normal"); the API takes codes
  (`N`/`A`/`F`) — widened to `string`.
- `view=detailed` on the documents list adds `client`, `obs`, `payments` — but NOT
  line items (verified against the live API); fetching `/documents/{id}` per document
  is genuinely the only way to get items.

## Checks

```sh
bun test && bun run typecheck && bun run lint && bun run format
```

Tests cover the financial summary math (`summarizeByType`, revenue net of credit
notes), utils (pagination, concurrency, number parsing, error mapping), and a
fixture-driven `buildPnlData` regression test with fetch mocked at the HTTP
boundary.
